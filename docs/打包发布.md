# TMD 打包与发布指南

> 适用平台：macOS（开发机）。Windows 安装包需在 Windows 上打包或用 CI，见 §5。
> 相关文档：[git-multi-remote.md](git-multi-remote.md)（双远程同步）

## 1. 打包命令速查

| 命令 | 产物 | 用途 |
|------|------|------|
| `npm run build` | `dist/`（网页产物） | 只编译验证，不打应用包 |
| `npm run dist:dir` | `release/mac-arm64/TMD.app` | 日常自用的 Mac 应用（未压缩目录形式） |
| `npm run dist` | `release/TMD-x.x.x-arm64.dmg`（约 124MB） | 分发给别人的 Mac 安装镜像 |
| `npm run dist:install` | 同 dist:dir + 自动覆盖安装到 /Applications | **推荐日常使用**，一步到位 |

全部命令均**跳过 macOS 代码签名**（`CSC_IDENTITY_AUTO_DISCOVERY=false`）：
当前仅有的 Apple Development 证书不能用于分发公证，签名对自用与未公证分发
均无收益，却耗时 3-7 分钟。将来若购买 Developer ID 证书并配置公证，去掉
脚本里的该环境变量即可恢复签名流程。

打包耗时约 **8 秒**（2026-09-06 优化后；此前因 macOS 代码签名耗时 3-7 分钟）。
产物目录 `release/` 已在 .gitignore 中，不会进仓库。

> 速度原理：编译仅约 4 秒，慢的是 electron-builder 默认的 macOS 代码签名
> （Apple Development 证书，对自用无收益且不能用于分发公证）。
> 所有打包脚本均已通过 `CSC_IDENTITY_AUTO_DISCOVERY=false` 跳过签名；
> **将来配置 Developer ID 证书与公证时**，去掉脚本中的该环境变量即可恢复。

## 2. 日常发布流程（自己机器上更新）

```bash
# 1. 确认改动可用
npm run build

# 2. 打包并覆盖安装（一条命令）
npm run dist:install

# 3. 启动验证
open -a TMD
```

**关键提醒**：文件关联（Finder 双击 .md 用 TMD 打开）绑定的是
`/Applications/TMD.app`。只跑 `dist:dir` 不覆盖安装的话，
双击 .md 打开的永远是旧版。

## 3. 正式发布（触发 CI 自动打包 + 双源发布）

日常自用更新见 [§2](#2-日常发布流程自己机器上更新)，这里只讲正式发布流程。

```bash
# 1. 改 package.json 的 version
# 2. 更新 docs/需求说明.md 里对应版本的完成状态
# 3. 提交
git add -A && git commit -m "chore: bump to v1.0.0"
# 4. 打 tag 并推送（触发 CI）
git tag v1.0.0
git push origin master --tags
# 5. CI 自动：打包 → GitHub Release → Gitee Release + raw 目录
```

CI workflow 见 [§7](#7-ci-发布工作流)。

版本号三处保持一致：
- `package.json` 的 `version`
- `docs/需求说明.md` 里对应版本的完成状态
- git tag 名（`v` + version）

## 4. 签名与公证（macOS 分发给别人时）

当前状态：打包时 electron-builder 会自动用本机的 **Apple Development 证书**签名
（日志里 `signing ... identityName=Apple Development: ...`）。

| 分发范围 | 需要什么 | 现状 |
|----------|----------|------|
| 自己机器 | 无 | ✅ 可直接用 |
| 别人的 Mac | Developer ID 签名 + 公证（notarization） | ⚠️ 未配置 |

未公证的 app 发给别人时，对方首次打开需右键 → 打开（绕过 Gatekeeper），
或在系统设置 → 隐私与安全性里手动放行。要正式公证需要：

1. Apple Developer Program membership（$99/年，Development 证书不能公证）
2. 创建 **Developer ID Application** 证书
3. `package.json` → `build.mac` 增加 notarize 配置（Apple ID + App-specific password）

## 5. Windows 安装包

`build.win.target = nsis` 已配置，但 **macOS 上打不出完整的 Windows 包**
（nsis 打包在 mac 上可以产出，但未实测且签名需要 Windows 证书）。可行路径：

1. 在 Windows 机器上：装 Node + 依赖后跑 `npm run dist`
2. 或配置 GitHub Actions CI（GitHub 仓库已有）：push tag 自动在
   windows-latest 上打包并上传 artifact —— 后续可加 `.github/workflows/release.yml`

## 6. 常见问题

### 6.1 打包时 Electron 二进制下载失败

GitHub 直连问题，用镜像手动补：

```bash
ELECTRON_MIRROR="https://npmmirror.com/mirrors/electron/" node node_modules/electron/install.js
```

electron-builder 阶段同样加 `ELECTRON_MIRROR` 环境变量前缀。

### 6.2 「打开方式」里看不到 TMD

- 必须用**打包安装到 /Applications** 的版本（开发模式的 Electron 壳不会注册）
- 新装后等几秒或注销重登（LaunchServices 缓存），也可强制刷新：

```bash
/System/Library/Frameworks/CoreServices.framework/Frameworks/LaunchServices.framework/Support/lsregister -f /Applications/TMD.app
```

### 6.3 双击 .md 打开的还是旧版

打包后没有覆盖安装到 /Applications。执行 `npm run dist:install`。

### 6.4 包体积

当前约 **293MB**（2026-09-06 优化后）。构成：

- Electron 运行时（Chromium + Node + 框架）：约 250MB，**不可压缩**，Electron 应用的固定成本
- app.asar（应用代码）：约 6MB —— 所有依赖已由 vite 编译进 `dist/`，
  全部依赖放在 `devDependencies`，electron-builder 因此**不再打包 node_modules**
  （历史版本曾因生产依赖被打包而多达 489MB，mermaid 一个包就占 81MB）

注意：**新增依赖时一律加到 `devDependencies`**（`npm i -D`），否则 node_modules
会重新被塞进安装包。

### 6.5 自动更新

已接入 electron-updater，双源策略（Gitee 国内默认 + GitHub 备用）。
设置面板提供"启动时自动检查更新"开关与"检查更新"按钮。

- 发现新版本时弹窗问用户是否下载（不静默下载）
- Gitee 失败自动切 GitHub 重试一次
- macOS 未签名场景：关闭签名校验（自用）
- Gitee 源策略：元数据放仓库 raw 目录，大文件挂 Gitee Release 附件
  （详见 [§7](#7-ci-发布工作流) 的 Gitee 上传逻辑）
- Gitee raw 有 CDN 缓存（约 5 分钟），发布后稍等再检查


## 7. CI 发布工作流

配置文件：`.github/workflows/release.yml`，push tag `v*` 自动触发。

### 7.1 工作流设计

两个 job：

| Job | 平台 | 职责 |
|-----|------|------|
| `build` | macos-latest + windows-latest（并行） | 打包 + 上传 GitHub Release + 上传 artifact |
| `publish-gitee` | ubuntu-latest（依赖 build 完成） | 下载两平台 artifact + 上传 Gitee |

### 7.2 Gitee 上传逻辑

1. **元数据推仓库 raw 目录**：`latest*.yml` 通过 Gitee API 的
   `PUT /contents/releases/{name}` 更新（失败则 `POST` 创建）。
   这样 generic provider 的 `raw/main/releases/latest-mac.yml` URL 能访问到。
2. **大文件挂 Release 附件**：先 `POST /releases` 创建 Release，
   拿到 ID 后逐个 `POST /releases/{id}/attach_files` 上传 dmg/exe/blockmap。

### 7.3 需要配置的 Secret

| 仓库 | Secret | 用途 |
|------|--------|------|
| GitHub | `GITHUB_TOKEN`（自动提供） | 写 GitHub Release |
| GitHub | `GITEE_TOKEN`（手动配） | 调 Gitee API 上传产物 |

到 GitHub 仓库 `Settings → Secrets and variables → Actions → New repository secret`，
加 `GITEE_TOKEN`，值从 Gitee `设置 → 私人令牌` 生成（勾选 `projects`、
`issues`、`pull_requests` 权限）。

### 7.4 手动触发

GitHub Actions 页面可用 `workflow_dispatch` 手动触发，用于测试 CI 流程。
